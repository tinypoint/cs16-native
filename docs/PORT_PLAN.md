# 原程序迁移路线 · 2026-10-23

## 已确认的范围

用户明确要求迁移原版 CS 1.6 程序，保持原引擎与游戏逻辑，以原程序转换加宿主接口适配为技术路线。macOS 为 ARM64 本机运行，Web 为浏览器本地执行 Wasm。不使用 Xash3D、ReGameDLL 或重建客户端替换原程序，不使用远程串流替代 Web 本地运行。

“原版”描述迁移原则，不等于已经证明上传整合包的每个文件均为官方未修改文件。哈希固定当前输入，附带的 VPN、辅助工具、第三方插件不参与当前核心程序实验，也未运行。

## 输入与格式

- 启动器：`hl.exe`／`cstrike.exe`，32 位 PE，包含窗口、系统与动态加载接口。
- 引擎：`hw.dll`／`sw.dll` 使用旧 GoldSrc classic BLOB。保留原文件，通过格式解码获取内存映像、入口和导入，不能直接交给只接受 PE 的转换器。
- CS 客户端：`cstrike/cl_dlls/client.dll` 同为 BLOB，需要迁移其中的原始代码。
- CS 服务端：`cstrike/dlls/mp.dll` 为标准 32 位 PE；`liblist.gam` 指向它。
- 文件系统、VGUI、声音及其他随游戏提供的 DLL 需逐项确定依赖，不能默认所有 DLL 都由同一引擎文件替代。

BLOB 格式资料来源：[goldsource-dll-decryptor](https://github.com/oxiKKK/goldsource-dll-decryptor)。当前实现仅依据格式读取节表和导入并生成分析映像，不复制其 Windows PE 重建器，不执行它附带的二进制，也不使用公开泄露的引擎源代码。

## 分阶段推进

1. **输入审计**：固定文件哈希、压缩包 CRC、模块结构与资源清单。已完成第一轮。
2. **格式与转换实验**：PE／BLOB 分别读入；发现候选入口、跟随直接分支和调用生成 C。漏检的回调、虚表和运行时入口仍需补齐，函数计数不等于完整覆盖。
3. **语义对照**：选择可隔离的真实函数，ARM64／Wasm 与 x86 参考比较寄存器、定义的标志位和内存。第一批已完成；不能据此宣布完整引擎正确。
4. **宿主运行时**：移植多模块地址空间、导入与导出、原加载器 BLOB 初始化、回调、线程、CRT／Win32 接口；评估红警既有通用部分的复用，保留两个项目的独立构建。
5. **原始渲染／声音适配**：让原始引擎渲染逻辑通过宿主接口工作。原程序使用的 Windows 图形／声音接口需要桥接；WebGL 与旧桌面图形接口存在差异，不能假设直接映射。
6. **可玩验证**：原菜单、实际地图、移动视角、射击换弹、购买、回合与设置。先本机，再浏览器。
7. **手机与持久化**：触摸设计与用户讨论后实施；资源以内容哈希缓存，设置另存，程序增量更新不重复下载大资源；Safari 内存与页面生命周期单独验证。
8. **联机**：保留原协议逻辑，验证浏览器网络转发所需的边界；不承诺直接加入任意服务器或完整反作弊兼容。

## 必须保留的诊断

转换失败、未实现指令、没有可靠终止边界、未解析的导入／回调都应显式报错或记录，不能用返回零／空函数掩盖。批量输出在未实现指令处放置失败即停的 abort，且带缺口时工具返回非零；这些产物不是可运行版本。模块批量 C 生成仅为实验；只有在编译、链接、加载与行为验证后才能升级为运行证据。

当前没有完整游戏启动器、可玩网页或对局成功记录；资源与程序均保存在被 Git 忽略的目录。无需重复上传已收到的压缩包。
